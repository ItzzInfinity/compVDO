### Quality Ladder (Android-specific)

Media3 Transformer has **no CRF**. It uses `VideoEncoderSettings` with a **bitrate** target on the hardware `MediaCodec`. The ladder maps modes to a **bitrate ratio** of the source:

| Mode | Bitrate target | Bitrate mode | Expected result |
|---|---|---|---|
| `LOW` | 25% of source bitrate | VBR | 75–85% smaller, softer |
| `MEDIUM` (default) | 50% of source bitrate | VBR | 55–70% smaller |
| `HIGH` | 75% of source bitrate | VBR | 40–55% smaller, near-lossless |

> [!IMPORTANT]
> **`ARCHIVE` mode does not exist on Android** — there is no FFV1 on MediaCodec, and no way to do true lossless. The UI must not offer it (per the architecture doc).

The output MIME is always `video/hevc` (H.265) — every Android device since API 26 has a hardware HEVC encoder.

### Rules Implementation (from `requirements.md`)

| Rule | Android implementation |
|---|---|
| R1.1 | Output via MediaStore: `<stem>_compressed.<ext>` beside original |
| R1.2 | Collision check on MediaStore URI; append ` (2)` etc. |
| R1.4 | `_compressed` files excluded from scan |
| R2.1 | Transformer writes to a temp file; final via MediaStore insert |
| R2.2 | Delete requires user toggle + verification |
| R2.3 | `MediaStore.createTrashRequest()` on API 30+; direct delete with confirmation below |
| R5.1 | Rotation preserved by Transformer (hardware handles display matrix) |
| R6.1 | Audio passthrough via `Transformer.Builder().setRemoveAudio(false)` — audio is stream-copied by default |
| R7.1 | Before/after size, ratio, time reported per job |
| R7.2 | GREW flagged, original kept |
| R8.1–8.3 | Duration check (±0.5%), dimensions check, playability check via `MediaExtractor` |
| R9.1 | Sequential by default (hardware encoder is the bottleneck) |
| R10.3 | bpp ranking, same arithmetic as Python |
| R12.1 | Compose UI never blocks; encode on foreground service |
| R12.4 | Material 3, dynamic colour, system light/dark |

### Makefile & Semver Versioning

#### [NEW] `Makefile` (project root)

```makefile
make build    # bumps patch version, builds debug APK, copies to ./build/
make release  # bumps patch version, builds release APK (unsigned)
make clean    # cleans Gradle caches
make version  # shows current version
```

#### [NEW] `android/version.properties`

```properties
major=0
minor=1
patch=0
buildNumber=0
```

Every `make build` or `make release`:
1. Reads `version.properties`
2. Increments `patch` and `buildNumber`
3. Writes back to `version.properties`
4. Sets `versionName` and `versionCode` in Gradle via the properties file
5. Builds the APK
6. Copies the APK to `./build/compvdo-<version>.apk`

> [!IMPORTANT]
> **NO git commit/push ever happens.** The Makefile only touches `version.properties` and builds. Version control automation is purely local file-based.
